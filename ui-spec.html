Studio Shell — UI Specification

The canvas-first workspace UI for Playground Ceramics, applied across the dashboard and all five apps behind a switchable view mode. Every numbered area below documents what it is, how it behaves, and the real code it binds to. This page is the Phase 0 sign-off gate: approve it and implementation begins; the existing UI is never removed.

1Overview & view-mode toggle

Two UIs coexist. Classic is today's UI and remains the default. Studio is the new shell. One switch flips between them per browser.

AspectBehavior
Resolution order?ui=studio|classic URL param → localStorage['playground-ceramics-ui'] → default classic. A URL param persists itself (same convention as ?project=).
Applied how3-line inline script in each page <head> sets <html data-ui="studio"> before first paint (no flash). All Studio CSS is scoped under that attribute; classic stylesheets are never edited.
DOM strategyReparenting, not duplication. In studio mode a shared studioShell.js builds the floating islands and moves the live classic DOM into them (the whole #parameterPanel, the export button, project name). Every existing event binding survives because the nodes themselves move. Classic markup stays the single source of truth.
SwitchingClassic: settings menu (⚙) gains an Interface: Classic / Studio row. Studio: topbar ⋯ menu gains Switch to classic UI. Switching persists the choice and reloads the page (all apps autosave, so nothing is lost).
Wheredashboard.html, index.html (Dinnerware), vessel-generator, vessel-v2-generator, handle-generator, cast-form-generator. mold-generator/ is excluded (not in the Vite build, not linked from the dashboard).
Default stays classic until you flip it after review — then it's a one-line change in scripts/ui/studio/studioMode.js.

2Focus button 36px corner · top-right

Behaviors
Click or F enters focus mode: every island slides toward its screen edge and fades, canvas zooms subtly, one exit chip remains (area 11). Esc or F exits. Inputs/selects never intercept the shortcut. Modals are never hidden by focus.
Backed by
CSS class on the shell root; ~20 lines in studioShell.js. No app code involved.

3Items button + collapse handle 36px corner · top-right

Behaviors
Toggles the Items/Parts panel (area 7). Accent-tinted when open. Small drag-handle bar beneath it is a secondary affordance for the same toggle.
Backed by
itemsPanel.js; hidden entirely for apps with no item list (see per-app matrix).

4Left tool rail 44px wide · top-left

Contents
Only controls that exist in each app today: Parameters (opens area 5) · app-specific mode buttons (Cast Form: Case box editor; Handle: mug display modes; Vessel V2: pen tools) · Cross-section · Grid · Canvas tone. Hover shows label chips (120ms delay).
Backed by
Adapter config per app calling real viewport methods, e.g. Dinnerware ViewportManager.toggleCrossSection() / toggleGrid() / setBackgroundColor() in scripts/ui/viewport.js.
States
Toggle buttons show accent-active state; Parameters button lights while the panel is open.

5Parameters panel 300px · opens at x72 · toggleable

Contents
The app's entire existing #parameterPanel, moved live into the island and restyled — every slider, number field, select, and dynamically-generated section (surface patterns, per-item overrides, motif inspector) keeps its bindings. Sections stay collapsible.
Behaviors
Opens beside the rail (never over it); view cube slides right to stay clear (area 6); chevron in the header collapses it; scrolls internally; status footer pinned at bottom (area 10).
Backed by
Reparenting in studioShell.js + scoped restyle of existing classes (.panel-section, .parameter-row) under html[data-ui="studio"].

6View cube 40px · CSS-3D · manipulable

Behaviors
Drag to orbit the actual camera; orbit the canvas and the cube follows; click a face to snap to that view; hover reveals a reset-to-¾ button. Full spec + live demo in section 3.
Position
Right of the rail when the panel is closed; slides +312px to sit right of the open panel. Order is always rail → panel → cube.
Backed by
viewCube.js ↔ each viewport's getCameraRig() (new, additive) exposing camera + OrbitControls.

7Items / Parts panel 272px · right · toggleable

Contents
One row per item/part: glyph, name, and an eye that hides/shows the real mesh in the scene. All / None shortcuts and a live count in the footer. Vessel V2 lists profile points as selectable rows (no eyes).
Behaviors
Eye toggles fade the mesh (e.g. Dinnerware writes ui.visibleItems then viewport.updateVisibility(); Cast Form calls setPartVisible('wall2', false)). Row click selects/highlights where the app supports it. The right dock (area 8) slides left so nothing overlaps.
Backed by
itemsPanel.js + per-app adapter (list source, visibility setter, change subscription).

8Right tool dock 44px · right edge · app-specific

Contents
Only real actions: Cast Form → Import STL/OBJ (existing import flow); Vessel V2 → pen/edit tools proxying the existing profile toolbar. Dinnerware/Vessel/Handle have none — the dock simply isn't rendered.
Behaviors
Docks to the right edge; when the Items panel opens it animates 284px left to sit just beside it — never overlapping.

9Warnings chip (lower-left) only when count > 0

Behaviors
Shows "⚠ N warnings"; click opens a popover listing each warning with details; click-outside or Esc closes. Absent entirely at zero warnings.
Backed by
Real validation systems: Dinnerware/Vessel warningSystem.subscribe() (scripts/utils/validation.js) · Cast Form castFormState.subscribe('warnings') · Vessel V2 profile validation feed.

10Panel status footer inside area 5

Contents
Ok/warn dot + count text per app: "7 of 7 items" · "4 parts + case" · "6 points · 360°". Updates live with visibility and state changes.

11Focus-exit chip focus mode only

Behaviors
The only chrome visible in focus mode. Shows "Exit focus · F"; click or key exits.

12Canvas (viewport) full-bleed · under all islands

Behaviors
The existing Three.js viewport promoted to fill the window (position:fixed; inset:0); existing ResizeObservers re-fit the renderer automatically. Grid, cross-section, and canvas tone are the app's real viewport features. Vessel V2 splits the canvas: profile editor (left) + revolved 3D preview (right), both always visible.
Backed by
CSS only — no changes to render loops, mesh generation, or export geometry.
